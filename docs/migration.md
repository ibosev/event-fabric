# Migrating an Application to EventFabric

For the approach, the phases and the `migrate-app` tool in brief, start with [Migrating an oblak Application](migrating-from-oblak.md); this page is the detailed reference.

EventFabric is a separate ESM package requiring Node 24.15 or later. CommonJS Applications use plain `require('event-fabric')`; no compatibility runtime or generated constants file is installed. The helpers below (`migrateSource`, `draftReadmodelSchema`, `migrateHistoricalEvent`, `migrateSagaState`, `auditReplay`, `auditFixtureFiles`) come from `event-fabric/migration`. Keep the source Application and its Event/Readmodel/Saga stores read-only throughout this procedure. Perform changes on a copy and a migration branch. Keep raw Application fixtures and audit reports outside the checkout. The [synthetic compatibility guide](migration-compatibility.md) and its executable example demonstrate the process with invented data and an explicit coverage manifest.

## Prepare the Application

1. Pin Node >=24.15 and verify every entry point with CommonJS `require(esm)`.
2. Upgrade HTTP routes and BFF controllers to Express 5. Replace WebSocket Commands/Events/Readmodels with HTTP and SSE; port existing SSE helpers to the public Gateway helpers and verify each client contract.
3. Remove socket objects from Command metadata; where needed, carry the socket's opaque id as explicitly mapped Application metadata. Decide how email-bearing metadata moves into erasable payloads before import. Keep ids in `auth.user`, `auth.channel`, `auth.account`, `auth.key` and `owner` where rebuilds read them. Remove `auth.socket`, `auth.platform` and `auth.forAccount`.
4. Find clock reads in Event handlers and Readmodel Reactions and replace them with the Event envelope timestamp. Inventory existing duplicate-effect behavior so migration comparisons distinguish inherited behavior from new regressions.
5. Audit deployments for old CLI invocations and clients for old HTTP headers and WebSocket use. During package coexistence call the new CLI by path: `node node_modules/event-fabric-next/dist/cli/main.js`. Change to the `event-fabric` bin after removing the vendored package.

## Command de-duplication

A Command id is accepted at most once in EventFabric's Event store (ADR-0014). If the source Application has a separate idempotency store or cached-response layer, migrate its contract explicitly before removing it; a replayed outcome and a cached HTTP response are different guarantees.

- HTTP clients send the standard `Idempotency-Key` header. Configure `idempotencyScope` on each Gateway that should honour it, and move clients that send `x-idempotency-key`. A retry replays the outcome with `EventFabric-Duplicate: true` instead of the old `x-idempotency-replayed: 1`, and its body renders the current Readmodel document rather than a cached response.
- Saga-set `metadata.idempotencyKey` values are no longer needed: a Saga's Commands commit with its Checkpoint (ADR-0011), and the Outbox re-sends a Command with its original id.
- The old `idempotency_conflict` becomes the Rejection kind `conflict` (HTTP 409). `idempotency_inflight` no longer exists: a concurrent duplicate waits for the first and returns its outcome.

## Mechanical migration and hand review

The repository supplies `dist/migration/index.js` after `npm run build`. These are development tools: `migrateSource()` lazily uses the installed ESLint JavaScript parser. Install development dependencies to run it. The framework and its production entry points never load ESLint. Tools return source strings and review lists; they never read or overwrite the source Application.

```js
import { migrateSource, draftReadmodelSchema } from "./dist/migration/index.js";
const result = await migrateSource(sourceFromACopy, {
  symbols: { "domain.sales.account.added": "sales.account.added" },
  // Supply exact expression replacements only after inspecting each call.
  replacements: { "require('<old-toolkit>')": "require('event-fabric-next')" },
  task: false, // true for a Task file
  saga: false, // true for a Saga declaration file
  packages: "coexistence", // "cutover" once the vendored package is gone
});
console.log(result.reviews);
// Write result.source only to the migration copy after reviewing it.
```

### The whole Application in one run

For an Application laid out in the old folders, `event-fabric migrate-app <folder>` (or `migrateApplication(folder, { check, packages })`) derives those options and runs `migrateSource` on every file. It rewrites the files in place, so run it only on the migration copy or branch, never on the source Application. With `--check` it writes nothing and exits 1 when a file would change; `--report <file>` writes each file's kind, change and review list as JSON.

- Sources are the `.js` files under `app/`, `lib/` and `plugins/`. Tasks (`app/tasks/`) are left alone: `event-fabric task` runs them in their old form.
- Kinds come from folders: `app/domain/<context>/<aggregate>.<context>.aggregate.js` Aggregates, `app/sagas/<group>/*.js` Sagas (`saga: true`), and `app/gateways/**` and `lib/**` with `legacyGateways: true`.
- The Event-name `symbols` are each Aggregate's `events` keys plus its generated `commandRejected`, read without running the files. They are given as `domain.<context>.<aggregate>.<event>` and as `events.domain.…`, so no generated constants module is needed.
- The old framework's package is the one whose toolkit the sources import (`require('<package>').tools…` or `'<package>/lib/tools…'`). Its REST toolkit becomes `legacyRest`, and imports of its `only` guards become EventFabric's: one-line ones, and `const { tools } = require('<package>'); const { only } = tools.domain.command;` where `tools` serves nothing else.
- `keepGetCrud` and, for Aggregates, `aggregate` are on: the composition root supplies `getCrud()` through `legacyApp`, `requestApp` and `legacyTaskApp`.
- `--patches <folder>` applies the Application's own decisions after the rules: unified diffs (`*.patch`, in name order, as `diff -u` or `git diff` write them against the rules' output). A hunk is applied only where its lines match exactly; one already applied is skipped, so a rerun keeps working, and one that matches neither way stops the run before anything is written. Keep decisions that no convention can supply here, such as a guard for malformed historical Events or a moved payload field, and the rules' review list says where they are likely needed.
- A file that a second run would change again stops the run before anything is written.
- It writes the composition root where a file is missing: `event-fabric.config.js`, `types.config.cjs`, `tsconfig.migration.json` and `migration/*` (local settings from `config/config.json5`, declarations over `legacyApplication`, orchestration, effects, services with the CRUD models of `app/crud`, Gateways for each `app/gateways/<kind>/<name>` folder over `legacyGateway`, and the historical Event conversion). The config runs those Gateways on their old ports, and its `setupServices` builds the old services (`gatewayServices`); a plugin hands them the running Application for system Notifications and for the tasks they schedule, which wait for the scheduler Saga when an old service schedules one while it is built. Runtime roles stay off until the Application sets `sourceMigrationReady` in its patch set, once its source reviews and Readmodel schemas are resolved. Their decision tables start empty, and the module aliases come from `package.json`'s `_moduleAliases`. `package.json` gains the EventFabric dependency (`--dependency <spec>`, by default a `file:` link to the running package) and its Node.js engine. Afterwards run `npm install` and `event-fabric types`.
- A patch section from `--- /dev/null` creates its file, so the patch set also carries the files only the Application has (reviewed Readmodel schemas, say) and its decisions over the generated composition root. A section to `+++ /dev/null` deletes its file; it must list every line, and a file already gone is skipped.
- `--packages cutover`, run on the migrated Application once its sources import nothing from the old framework (move what they still use, such as its error classes, into the Application first, through the patch set) and its dependency is removed: `event-fabric-next` becomes `event-fabric` in the sources and in the composition root (`event-fabric.config.js`, `types.config.cjs`, every module under `migration/`), and `package.json` moves the dependency to `dependencies` as `event-fabric`. Pass a separate patch folder with the Application's cutover decisions (its old entry points, say). Then run `npm install` and `event-fabric types` again.

### Old behavior is the default

The transforms keep what the old stack did, using today's API, wherever that API can express it; where it cannot, the source is left unchanged and listed. EventFabric's own semantics stay available on top: each preserved behavior is visible at its call site, so the Application can adopt the new one later, case by case.

Some old behavior needs no rewrite, because the runtime keeps it:

- An `eventEnricher` that sets `event.metadata` fields and returns nothing keeps those fields; a returned object is still merged into metadata. The rest of the Event stays frozen. `migrateSource` wraps old enrichers in `legacyEnricher` (below), which also keeps their old timing.
- A Readmodel's `reactionSets` hold the old grouped `<event>:<group>` keys that had their own Identity, query entry or markers: each Reaction set reacts to the model's Events with its own `identity` and `reactions` on the same documents, after the model's own Reactions and in declaration order. Where two sets select the same document, the second sees the first's change; the old stack loaded and saved the document once per group, in no defined order.
- Readmodel and Saga Reactions keep the old markers' meaning. `{ settings: { autoCreate: false } }`, like `only.ifExists()`, handles only existing documents and instances; `autoCreate: true` was the default. `{ settings: { shouldHandleEvent } }`, the old Saga `{ shouldHandle }` and the new `only.if(predicate)` skip the whole Reaction when the predicate returns false: no function runs and no document or instance is created. The predicate receives `(event, view, app)`, so the old one-, two- and three-argument Saga predicates all work. The old toolkit's `only` therefore keeps working. To use EventFabric's `only` instead, replace its import through `replacements`; `migrateSource` then removes each old `only.ifNotExists()` from Reactions, since it allowed creation and still handled existing documents, while the new marker of that name skips existing ones. In Aggregate Commands both markers mean the same in both stacks and are kept.

The others are rewritten to a call of a small helper from `event-fabric/compat` (`event-fabric-next/compat` during coexistence). `migrateSource` adds one `require` or `import` for the helpers it used:

| Helper | Old behavior it keeps | Emitted for |
|---|---|---|
| `legacyMetadata(metadata, command.metadata)` | Applied Event metadata was the Command's metadata deep-merged over the Event's, Command values winning (`lodash.merge`), merged into the Event's object in place; the new merge is shallow and the Event's values win | `aggregate.apply.<event>(payload, metadata)` in a `(command, aggregate)` Command function |
| `legacyQuery({ filter, sort, from, size, q })` | The QueryBuilder envelope: a field whose value is `undefined` sets no condition, an array value is membership, `ne` with an array is `nin`, `$oneOf` is `oneOf`, `id` is the document id, sort records take `'asc'`/`'desc'`, an omitted size is 100 and size 0 is unlimited | every chain of `find`, `filter`, `sort`, `from`, `size`, `q`, `exec` on `getReadmodels().<group>.<model>()` |
| `legacyOne(<model>(id))` | `await <model>(id)` resolved to an array: the document, or empty | an id read |
| `legacyStream(<model>.stream(…))` | `.stream()` was a Node object stream (`.pipe`, `.on('data')`) | a chain ending in `.stream()` |
| `legacyQueryIdentity(query)` | A separate `query` map selected the documents an Event updates; the filter uses the old operators | each `query` entry, moved into `identity` |
| `eventEnricher: legacyEnricher(fn)` | The enricher ran inside each `apply`, before that Event's fold: it saw the State before the Event, could change or return the whole Event, and later Steps and Rules saw what it changed. Only the payload and metadata are recorded; changing another envelope field rejects the Command | every old `eventEnricher` |
| `legacyList('<group>', '<model>', { query, transforms })` | The old list route: the request's query string in the old syntax (below), overridden key by key by the route's `query`, answered as `{ total, data }`; transforms run in order on each document | `readmodels.list(m => m.<group>.<model>, { query, transforms })` |

The runtime still refuses, before any Event is processed, what it cannot honor: a non-function Identity (an old property-path string), inline `useAsId`, any other non-function Reaction item (extenders) and an unknown key. `migrateSource` lists those forms without rewriting them.

`compile()` refuses what it would otherwise drop, so a migrated Aggregate fails loudly instead of changing behaviour: an unknown top-level key (an old `options` block with `disablePersistence`, `skipHistory`, `applyLastEvent` or `version`; Events are always persisted and history always loaded), and a global Rule that is not a function (a named `{ name, description, rule }` object: pass `rule` and keep its rejection code in the Rejection it throws). Removing an `options` block is a decision per Aggregate: an Aggregate that persisted nothing now records its Events, so decide whether its Commands should become Events at all, or whether the work belongs in a Worker. The validator fails a schema naming an unknown format instead of skipping the check. A `formatsDir` module exporting `{ name, options }` registers under `name`, as before; other modules register under the file name before its first dot. `schemasDir` refuses JSON5 and YAML files; convert them to JSON or JavaScript.

Run the Event-name replacement in one commit across every consumer in the Application inventory. Supply a complete expression-to-qualified-name map from the compiled model, including Command constants. Names are `'<context>.<aggregate>.<event>'`. Delete the generated constants import only when every use is replaced. Rejected pseudo-Events become rejected Command outcomes. Every Event name in the imported log must stay declared, including Events the Application no longer emits: `start` and `migrate` refuse a log with undeclared names. Keep a retired Event declared with a no-op handler.

The AST transforms preserve comments and string contents. Package targeting is explicit. With `packages: 'coexistence'` (the default), `event-fabric-next` imports stay as they are, and imports of `event-fabric` are listed, since during coexistence that name is the vendored old package. With `packages: 'cutover'`, applied once the vendored package is removed, `event-fabric-next` and its subpaths become `event-fabric`. Subpaths the new package does not export are listed in both phases. An empty review list means no known pattern was found, not that the copy works: run the copy's tests and representative Tasks and routes. Running `migrateSource` again on its own output changes nothing. The transforms convert `getCrud()` to `getServices().crud` (with `keepGetCrud: true` they leave it, for an Application that supplies it itself; see below), per-Command scratch properties to `locals`, remove the obsolete `hasSnapshot` response field, and rewrite:

- **Aggregates.** A callable `aggregate.apply('<event>', payload, metadata)` becomes `aggregate.apply.<event>(…)`. A computed name that is surely a string (a template, a concatenation with one, or a variable only ever assigned such values) becomes `aggregate.apply[name](…)`; any other computed name inside a Command function is listed. Metadata passed to `apply` gets `legacyMetadata` with the Command's metadata: `command.metadata`, or the destructured `metadata` binding, which is added to the pattern (`metadata: commandMetadata`) when missing. Where the Command is not in scope (a helper taking the Aggregate) or its pattern has a rest element or a default, the call is listed. An awaited `getDomain().<c>.<a>(id)` read becomes `….load()`, the State, whose `get(path)` and `revision` replace the old model's `get()`, `toJSON()` and `getRevision()`. Every old Revision read becomes `revision`, which is kept outside the State attributes: `getRevision()`, `_aggregateModel.getRevision()`, `._revision`, `.attributes._revision` and `get('_revision')`. `_aggregateModel.attributes`, a loaded State's `(await getDomain()….load()).attributes` and a Rule's `current.attributes` or `previous.attributes` become `get()`, a read that includes the Stream id as `id`, as the old attributes did; changes go through `set()`. The old model's `_revision`, `_revisions` and `_destroyed` are not in it.
- **Event envelopes.** On the Event parameter of an Event handler, Reaction, Identity or enricher, the old string `event.context` becomes `event.context.name`, and the commit time `event.metadata.timestamp` becomes `event.timestamp`, an ISO string; check code that expected a Date or a number. The same paths elsewhere, such as a helper interpolating `${x.context}`, are listed. `event.aggregate.revision`, `.id` and `.name` are listed: Events carry `stream` and `revision` at the top level. In an Aggregate Event handler (a function written directly in its `events` map) whose Event pattern destructures `metadata`, `metadata.timestamp` and `const { timestamp } = metadata` become the Event's `timestamp`, added to the pattern (in place of `metadata` when nothing else reads it); a `timestamp` already bound there leaves the handler listed. Readmodel Reactions keep `metadata.timestamp` when the composition root hands them the old envelope. A Command step's `metadata.timestamp` (a destructured `metadata` and an `app` third parameter) becomes `metadata.timestamp ?? app.now`, the time of the attempt, since Command metadata carries no commit time.
- **The Application's own defects stay out.** Clock reads in Event handlers and Reactions, JSDoc types newer TypeScript rejects and similar defects are bugs on the old stack too: fix them in the old source first, with a tool that writes only the old framework's API, so the fixes can ship before the migration. An old-envelope read the fix leaves (`metadata.timestamp` in an Aggregate Event handler, `event.metadata.timestamp`) is migrated like any other.
- **Enrichers.** Every old `eventEnricher` becomes `legacyEnricher(…)`, which keeps the old timing and the mutable Event. Without it an enricher runs once per Event after every Step and Rule, sees the final State and adds metadata only; remove the wrapper where that is what the Aggregate needs.
- **Readmodels.** A `query` map moves into `identity` through `legacyQueryIdentity`; a key in both maps is listed. Grouped `<event>:<group>` keys without their own Identity, query entry or markers become one Reaction for the Event that runs their functions in source order. The others move into `reactionSets`, one set per group, keeping their own Identity (a query entry through `legacyQueryIdentity`) and markers; a set without its own Identity gets its Event's, as merged groups do. A group keyed by its Event's query entry is listed. The old `only.ifNotExists()` is removed from Reactions.
- **Sagas** (`saga: true`). An Event without an Identity gets `(event) => event.id`: the old store started a new instance for each such Event, and the Event id keeps one instance per Event deterministically, where the new default, the Stream id, would merge them. Key it by a payload field instead where later Events must reach that instance. Keys that are Event-name constants count as the names `symbols` renames them to, so this happens in the same pass. Each entry follows the map's key form (a renamed constant becomes `["<name>"]`); a map written over several lines gets one entry per line at its indentation, after any trailing comma and comment. `initialState` is removed and listed: the old Saga builder ignored it, so every instance started empty. Both apply where `identity` and `reactions` are object literals or variables declared once with one, also under computed string keys (`['a.b.c']`).
- **Queries.** A QueryBuilder chain becomes one `find(...legacyQuery(…))`, or `legacyStream(….stream(...legacyQuery(…)))`, and an id read `legacyOne(<model>(id))`, keeping the old filters, defaults and result shapes; a `const` holding `getReadmodels()` (`const rms = req.getApp().getReadmodels()`) counts as the call. A text search (`q`) is listed: it now needs a declared text index and matches case-insensitive substrings and phrases, not Mongo `$text`. `await <app>.getReadmodels().<group>.<model>().base().<Mongo chain>` becomes `await (await <app>.getReadmodels().<group>.<model>.native()).<Mongo chain>`: the old `base()` was the Mongo collection, so the chain keeps its meaning, but only on the Mongo Readmodel store; it is listed for porting to `find(filter, options)`. A `$lookup` (or `$graphLookup`, `$unionWith`) into another group's model needs both groups in one database (the Mongo store's `databases` option) and an index on the joined field; the old collection name resolves as the model name. Any other `base()`, a chain with another old method (`raw`, `options`, `toArray`, an id read with methods) a `getReadmodels()` result kept in a variable (for its other uses), and a bare `<group>.<model>()` builder that is passed on or kept instead of awaited (it may still be used as a builder) are listed and left unchanged.
- **Lanes.** The old stack had one Command queue, so an import or a slow handler held up users. Give machine-facing Gateways (the REST API, webhooks) `lane: 'bulk'`, and leave the browser Gateways interactive. Sagas, Schedules, Workers and Tasks already send bulk.
- **REST.** An old command descriptor, `command(domain => ({ command: domain.<c>.<a>.<command>, event: 'readmodel.<group>.<readmodel>.<change>' }), { id: req => …, payload: req => … })`, becomes `command((req) => ({ stream: { context, aggregate, id }, name, payload }), { respondWith: '<group>.<readmodel>' })`, and it is listed because the response changes: the `respondWith` document whose id is the Stream id (202 with the Outcome while it is not written yet), or the Outcome, not the old Notification payload or `{ aggregate, payload }`. A descriptor with transforms, schema, a missing `id` or `payload` option or a domain Event wait is listed with the same translation and left unchanged; a Readmodel with another Identity needs its own handler. `readmodels.list(m => m.<g>.<m>, { query, transforms })` becomes `legacyList('<g>', '<m>', { query, transforms })` and is listed, since errors, negative paging, text search and the transforms' second argument change (below). A list with other options, such as the old `schema`, which serialized each document as `{}`, and old `readmodels.one(m => m.<g>.<m>)` helpers, `req.getApp()` and a top-level `access['*']` default (now ignored) are listed and left unchanged. To keep whole old Gateway folders instead, serve them with `legacyGateway` (below), replace the toolkit's import with `require('event-fabric-next/compat').legacyRest` through `replacements`, and pass `legacyGateways: true` for the route and helper files: descriptors, Readmodel route helpers and `req.getApp()` then stay as they are. Other `readmodel.…` strings, including an `event` field in Application data, are left unchanged and listed: their use cannot be found mechanically.
- **Application accessors.** `getLogger()` and `getWorkers()` are listed: use the context's `logger`, and record Worker work with `queue(…)` so the Outbox delivers it after commit. In an Aggregate file (`aggregate: true`), where every Application is a Command context, `<app>.getLogger()` becomes `<app>.logger`.
- **Forked Tasks.** `fork(<root>/distributed.js, ['task', file, …args], { env })`, the old framework's process entry running a Task, becomes a fork of EventFabric's CLI (`cli/main.js` beside the package's entry), with `--` before the Task's arguments. An `env` that only copies `process.env` keys becomes `process.env`, since EventFabric reads its settings from the environment.
- `<app>.getDomain().<context>.<aggregate>(id).<command>(payload, metadata).await('domain.<c>.<a>.<event>')` keeps `.await` with the `domain.` prefix removed when `<c>.<a>` is the Command's own Aggregate. Otherwise it becomes `<app>.awaitCorrelated({ stream, name, payload, metadata }, '<c>.<a>.<event>')`, which resolves to `{ status, event, outcome }` and does not throw on a Rejection. Where the result was declared (`const x = await …`), it becomes `const waited = …`, a Rejection throws `waited.outcome` as the old await threw, and `const x = waited.event` keeps the Event; other uses are listed. On the declared result of any wait, `x.aggregate.id` becomes `x.stream.id`. A non-literal pattern or a Command not sent through a direct `getDomain()` chain is flagged, because whether the wait is chain-wide cannot be decided.
- In an `access` map (a variable, property or `exports.access` assignment), a Readmodel rule returning `{ filter: { … } }` becomes the plain `{ … }` filter. A `filter` whose value is not an object literal (it could be a document field named `filter`) or that sits next to other keys is flagged.
- The `domain` section becomes `{ '*': true }`, which is what ran before: old Command rules were never enforced. The old rules stay as comments under `'*': true` and are listed for review; a map without `domain` gets `domain: { '*': true }`. `readmodels` `'*': true` wildcards are listed for tightening after cutover. A map with spread or computed keys is flagged. Review native queries against the chosen adapter; Mongo aggregation is explicitly Mongo-only. Unsupported constructs remain in source and receive review entries. Re-run lint, type checking and source searches after applying tools.

Old Task files can stay as they are. `event-fabric task <file> -- args` runs a module whose only export is the old `module.exports = async (task, app) => …` with `{ args }` and an old-style Application on the Task context: `getDomain()`, `getReadmodels()` (`group.model()` is the old query builder), `getServices()` and `getLogger()`. A `getDomain()` Command is sent as soon as it is built; `.await('domain.<context>.<aggregate>.<event>')` (the prefix is optional) waits chain-wide for that Event, resolves to it in the old notification shape and throws on a Rejection, as does a plain awaited send. Application-specific accessors come from a `legacyTaskApp(ctx)` export of the config module, merged over those, for example `exports.legacyTaskApp = ctx => ({ wire: { app: { config: oldConfig } }, getCrud: () => ctx.services.crud })`. Only the old command changes: `node distributed.js task <file> a=1` becomes `npx event-fabric task <file> -- a=1`. A Task that queries the old Event store's collection still needs porting to `readStream`/`readAll`.

To rewrite Task copies instead, pass `task: true`: a CommonJS Task export of `(task, app)`, `({ args }, app)`, `(task)` or `()` becomes `exports.run = (ctx, args)`, and its Application parameter becomes `ctx` (a shorthand `{ app }` becomes `app: ctx`). Any other `module.exports` is listed. Config reads become `ctx.config` and are listed: that is the EventFabric config, so the Application's own settings (such as a database URI) are not in it. Passing `ctx` to a helper is listed too, since a helper written against the Application's accessors fails on it. The Task context has fields, not the Application's accessors: `app.getServices()` becomes `ctx.services`, `app.getReadmodels()` becomes `ctx.readmodels`, and `app.getCrud()` becomes `ctx.services.crud`. A direct `app.getDomain().<c>.<a>(id).<command>(payload, metadata)` becomes `ctx.sendCommand({ stream, name, payload, metadata })`, and with `.await(…)` it becomes `ctx.awaitCorrelated(…)`. Both resolve to an outcome and do not throw on a Rejection, so check `status` where the old call threw. Any other `getDomain()` use is flagged. A Task process handles no Commands itself: a running Application replica on the same Transport handles them. Uses of the old Task helper require hand review. Consolidate repeated Mongo connection blocks into an Application-owned helper and service; EventFabric supplies no Mongo URI or connection registry. Replace old Event-store filters with `readStream`, `readAll` or an Application Readmodel. Remove already-run data-rewriting Tasks. Rewrite Tasks that read the old Event store, run a single document's Reactions and upsert the result as a whole-group `rebuild <group>`: EventFabric has no targeted rebuild by id, model, position range or Aggregate. The same applies to old `rebuild` CLI invocations with a model, position range or Aggregate. During the cutover rehearsal, time a full rebuild of the largest group on the imported log.


#### Old list routes

`legacyList` reads the raw query string with the old bracket syntax (`tag[ne][]=a`), without the prototype keys the old parser allowed. `from` (default 0), `size` (default 100; 0 is unlimited), `sort`, `q` and `aggs` (ignored) are reserved; every other key filters, `id` as the document id, and `minPosition` stays EventFabric's read-your-writes token. Paging takes a base-10 prefix (`12rows` is 12). A string value is comma-split membership, empty tokens kept; one value is equality and none drops the field. A `.gt`, `.gte`, `.lt` or `.lte` suffix is a range on the field before it, merged in key order with the field's other conditions, and a range wins over `ne` on one field. `sort` is `-a,+b,c`; a repeated field takes its last direction. `$oneOf` alternatives become `oneOf`, and an object without range or `ne` is an equality with that object. Values stay strings; nothing is coerced.

`total` counts every document the caller's Access map lets them read, before paging and transforms, in a separate read from the page. Transforms receive `(document, handle(req))`, not the old Application; one returning null or undefined drops the document. The response is `{ total, data }` with the Gateway's Position headers. Where it differs on purpose: a negative `from` or `size`, a `sort` array holding non-strings or a non-string `q` answer 400, and every error is the Gateway's `{ code, message }`, with `Bad Request` as the paging message, before any byte is sent, never a partial body. `q` is the store's text search, not Mongo `$text`.
#### Old Gateway folders

`legacyGateway({ directory, port, metadata, ... })` (from `event-fabric/compat`) returns a Gateway definition that serves an old Gateway folder unchanged: `setup.js` (`index.js` wins) supplies the Access map, and `routes/**` the `{ before, routes, after }` files. A folder is a path prefix, an `index` or `root` file mounts at its folder and `a.b.js` at `/a`; a route value is a function or array (GET), an operation or a map of methods, and nested arrays flatten. Express 4 paths translate (`/:hours?` is `{/:hours}`, a trailing slash is dropped); a path with `*`, `(` or `+` stops the start. Routes build on the first request, once services are ready.

- **Identity.** `metadata(req)` returns what the Application's auth middleware put on the request, read when used, as JSON (an ObjectId becomes its text). Each Access rule receives it; a missing `domain` section allows every Command, as the old stack never enforced it. `requestFields` are set on every request (the name old auth code records as its channel).
- **Toolkit** (`legacyRest`). `async(fn)` and `services(fn)` as before. `command(domain => ({ command, event }), { id, payload, transforms, schema })` sends the Command with the request metadata over its own and answers like the old Notification: for `readmodel.<group>.<model>.<change>` the document a Notification naming the Command's correlation names (read through the Access map; `create` and `update` both match a written document, `delete` a removed one), for an Event name `{ aggregate: { id, name, revision }, payload }`. Without that result within `waitTimeout` it answers `202` with the Outcome. `readmodels.one` reads `req.params.<model>_id` and answers `200` with an empty body when nothing matches; `readmodels.list` answers `{ total, data }` as `legacyList` does. Transforms receive `(document, req.getApp())`; null or undefined ends the chain.
- **Command routes and idempotency.** A toolkit `command` route answers the new Gateway's `EventFabric-Command-Id` and `EventFabric-Position` headers. `legacyGateway`'s `idempotencyScope(metadata)` (for example `(metadata) => metadata.tenant`) makes a request's `Idempotency-Key` the Command id within that scope, read after the route's middleware has set the metadata. A repeated key answers the first Command's Events with `EventFabric-Duplicate: true`; a route waiting for a Readmodel document answers `202` with the Outcome, since the first request wrote that document. Without the option the header is ignored, as the old Gateway ignored it.
- **Replaced Commands.** `replacedCommands` maps an old Command (`context.aggregate.name`) that is no longer a Command to `(req, { id, payload }) => value`: a toolkit `command` route naming it sends nothing and answers the value as it would the waited Event's `{ aggregate, payload }`, through the route's transforms; a throw answers as a rejection. Use it for a route that waited for an Event nobody stores any more, such as an `options` Aggregate's (below), and enforce the old Command's Access in the function: it does not run the Command's rule.
- **Serialization.** The old toolkit wrote each response with a serializer compiled from its response schema (`schema.responses[200]`, else the Readmodel's schema). Pass `serializer: (schema) => (value) => string` and `readmodelSchemas` to keep that output, field filtering included; without them responses are plain JSON.
- **Undeclared keys.** The old Readmodel store kept keys a schema did not declare, so a Command payload copied into a document could carry any key its API schema allowed. EventFabric documents are closed: such an Event halts the group. Give migrated Readmodel schemas `"x-undeclared": "drop"` unless the API schemas forbid extra keys.
- **Old accessors on Command and Reaction contexts.** The Application option `legacyApp(app)` adds members to the last argument of every Command step, Precondition, Rule and id generator and of every Readmodel and Saga Reaction, live and on rebuild: `legacyApp: app => ({ getCrud: () => app.getServices().crud })` keeps `app.getCrud()` working, so `migrateSource` can run with `keepGetCrud: true` and leave those calls unchanged. Built-in members win over the ones it adds. Gateways take `requestApp` and old Tasks the config module's `legacyTaskApp` for the same purpose. Declare the members once as `Register["legacyApp"]` (for example `legacyApp: { getCrud(): Crud }`): they then type those contexts and `req.getApp()`, and `legacyApp` and `requestApp` must return them. The lint rule against CRUD reads in Readmodels still reports `getCrud()` there.
- **`req.getApp()`.** `getServices()`, `getReadmodels()` (the Access-scoped Readmodels of `handle(req)`. The old accessor only refused a model without a rule and read unfiltered, so a rule whose filter names a field the model's documents lack hid nothing there and hides every document here: before cutover, check each filtering rule against the documents it covers. Called without arguments, `<group>.<model>()` is the old QueryBuilder: `find`, `filter`, `sort`, `from`, `size`, `q`, `raw`, `exec`, awaiting it for the array, `stream()`, and `base()` as the model's `native()` under the caller's Access filter, the scoped read-only Mongo view), `getDomain()` (request metadata over the caller's; `.await` takes a pattern or a list of them, as the old runner did, and raises the old error on a rejection; a wait route code never consumes raises nothing, as the old lazy one did), `awaitCorrelated(command, pattern)` for the chain-wide waits `migrateSource` rewrites (request metadata over the Command's; it resolves to `{ status, event, outcome }`), `getLogger()` and `errors`; `requestApp(app, req)` adds members such as `getCrud`.
- **Errors.** Answers keep the old body `{ error: { code, message, data } }` with the error's `statusCode` (default 500), without the old `stack`. A rejected Command's thrown error comes back as its class when `errors` has it (`data` or its `toJson()`), otherwise with only its name, message, `statusCode`, `errorCode` and `code` (another library's error may hold connection details); a schema rejection becomes the old `ValidationError.formAjvError` result. An Access denial is the old `UnauthorizedError` (401). JSON body errors answer the same way.
- **HTTP defaults.** CORS for every origin (`OPTIONS` answers 200), URL-encoded and JSON bodies up to `bodyLimit` (default 10 MB; JSON also as `application/vnd.api+json`) with `req.rawBody`, the extended query parser, `req.query` as a plain property that middleware may change (Express 5 parses it again on every read), `req.body` always set, and `404 Not Found.` as text. `afterRoutes(app, { services })` adds routes after the tree, before the 404, such as an old description route; the first request waits for it.
- **Route hooks.** `onRoute({ uri, method, operation })` is called for each route method as the old plugins' `onRoute` hook was: `uri` in the old path form, `operation` with its `handler` and its `schema` (the route file's `schema` merged in, arrays united). A toolkit operation's schema is the old one: a `command` has its Command's payload schema as `body` when `commandSchemas` (by `context.aggregate.name`) supplies it, and a `list` has the list response. Old documentation plugins (a swagger spec, schema routes) run this way unchanged. The hook receives copies of the operation's schemas (its own and those of the toolkit operations in its handler list): a plugin that rewrites them in place, as the old swagger plugin did, cannot change what a later build of the routes serves, after a failed build or in an Application restarted in the same process.

`legacyServices(directory, app, instances)` builds an old services folder the old way: each file named by its first name part under its folder's name, built in folder order with `init(store, app)`, as the old accessor tree (`services.team.auth()`), with `close()`. The store a factory receives has `get(name)`, `service(name)` and `services` by name, as the old one had. The `app` argument is the Application's stand-in for the old runtime object the factories read (config, connections, error classes).

#### The old socket protocol

When a folder's setup has `ws`, `legacyGateway` serves the old SPA socket on the Gateway's port (any path), with `ws` as an optional peer dependency. The connection middleware runs on a request with `params` (the query string, so `token`) and `socket.uniqueId` (the client's, or a new one); a throw refuses the upgrade with 401. Each message carries a copy of the connection's fields, which `incoming` middleware may change, and is answered as the old server did:

- `subscribeRead` reads through the Access map: a list answers `subscribedRead`, `stats` (`{ total }`), one `item` per document and `finish`; `single` answers its document alone. Documents are EventFabric's: the old stamp field is gone, and on the Mongo store an absent field stays absent, as the old stack stored it.
- `subscribeEvents` takes the old subset filter (`partOf`) over Events, Readmodel changes and Application Notifications, in the old notification shape (`fullname`, `type`, `name`, `payload`, `metadata`, `aggregate`, `readmodel`). A Notification `name` arrives as `system.<name>`. Events and Notifications pass the `live` option's rules, by the caller's metadata; Readmodel changes pass the Access map.
- `sendCommand` answers `sentCommand`, then sends the Command with the connection's metadata over the client's. The old client sends Commands without an id and waits with the filter `{ metadata: {} }`, which matched every client's Events; here such a wait belongs to the next Command the same socket sends, and receives its `commandReceived`, its Events, the Readmodel changes its correlation made, or `commandRejected` with the old error's fields.
- `sendToken`, `unsubscribeRead` and `unsubscribeEvents` answer as before; errors answer `{ type: 'error', statusCode, payload: { message, code, data } }`.

Deliberate differences: frames no longer echo the connection's data (the old server repeated the token in every one), Events are no longer sent to every client, `subscribtion` middleware is refused at start, and the server pings every 30 s and disconnects a client that does not answer or falls 4 MB behind. Neither stack re-subscribes after a reconnect: that stays the client's job.

Under load, `legacyGateway`'s `socket` option takes two settings:

- **`coalesce`** (milliseconds, off by default). It throttles each `subscribeEvents` subscription that is not a Command wait: the subscription delivers a Readmodel change at once, then at most one per window, the last one. A list that auto-refreshes reads again on any change, so it shows the same data. Use about 500 ms. Events and Application Notifications are not throttled.
- **`commandWaitTimeout`** (default 10 000 ms after the Command is accepted). A Command wait still open by then receives `commandRejected` with a `CommandTimeoutError` (`statusCode` 504), so a client awaiting a Readmodel change that was dropped or lags rejects instead of hanging. The old client has no timeout of its own. Its only exits are a name it awaits or a name ending in `Rejected`, and the server cannot see which names it awaits. The Command is recorded, and its Events were already delivered. HTTP routes answer this case with `202` and the Outcome.

A socket's Command waits share one live subscription per scope, and a change's correlation is checked before its Access filter. Other subscriptions take only their `readmodel` group and model. Without `outgoing` middleware, sockets share each notification and serialize it once, so every socket receives the same notification `id`.

### Composition root and services

`legacyApplication(options)` (from `event-fabric/compat`) loads an Application laid out in the old folders as declarations, keeping the old semantics the composition root would otherwise restate: Aggregates from `app/domain/<context>/*.js`, Readmodels from `app/readmodels/<group>/*.js` and Sagas from `app/sagas/<group>/*.js` (one Saga `<group>.<file>` per file, as the old store kept one state collection per file). It returns `aggregates`, `readmodels`, `sagas`, `orchestrationSagas` and `workers` for the config, plus `deferred`, `rejections` and `historical` for review.

- Readmodel and Saga code gets the old Event envelope (Context as a string, `fullname`, the Revision on `aggregate`, the commit time, `position` and `correlationId` in metadata), one copy per Event and group, as the old runtime shared it; Partitions of one group each keep their own Event's copy, and a batch that runs again starts from the recorded Event. Readmodels get the old view (array paths, `undefined` ignored, objects merged, `attributes`) and the stored `id`; old `query` entries become Identities, `<event>:<group>` keys become Reaction sets, and undeclared document keys are dropped with a warning. Each Readmodel's schema and indexes come from `readmodelStorage`.
- An `options` Aggregate's Commands queue the orchestration Worker, which runs the old Command on an empty State and sends each Event as a Saga Message to the Sagas reacting to it; `getServices().external.publisher().scheduleTask` schedules through the `system.scheduler` Saga's Deadlines. Contexts in `disabledContexts` keep only their Event handlers.
- Saga Reactions listed in `effects.reactions` run in their Saga's Worker; elsewhere a Saga's provider calls other than the listed reads are refused. Reactions to the old `commandRejected` pseudo-Event are dropped and listed in `rejections`.
- The Application's own facts are options: the groups loaded, Saga bindings and the groups each reads, Reaction keys the old runtime never matched, Event names in the log that no Aggregate declares, a `restoreEvent` hook for envelope fields an import moved, and per-Command orchestration checks.

The old registry discovered every service file, called each `init` factory in file-system order, did not await an async factory, and registered whatever it returned; a factory could read services registered before it. Write that order down explicitly in `setupServices`: construct each service after the ones it reads, `await` async factories (an improvement: a service is ready before anything uses it), and register each client's cleanup on `resources` right after acquiring it. A Task runs `setupServices` too, so services built by a plugin must move there. Keep CRUD Models and external clients Application-owned; `getCrud()` maps to the `crud` service.

Services that captured the Application to send Commands, publish Events or schedule work, including during construction, bypass the Outbox: copied unchanged, that work runs before or without the commit. Move it into a Command Step (`app.tell`), a Saga effect, or a Worker Message. Startup plugins that generate source or documentation files become build steps. Old deep imports into the package become its public subpaths (`migrateSource` lists the rest). Deployment selectors map to `run --only` role selections; verify each deployment starts the components it ran before.

Delayed Commands must be recorded in the Outbox. Inspect every inventoried `scheduleTask` call site: keep its target Stream, Command name, payload, inherited metadata, absolute due time and replace key. Replace the exact reviewed call expression via `replacements`, for example:

```js
app
  .tell()
  .sales.account(id)
  .remind(payload, metadata, {
    notBefore: dueAt.toISOString(),
    replaceKey: `reminder:${id}`,
  });
```

Unknown schedule signatures are deliberately flagged for review rather than guessed. Delays are not recurring jobs. Use an external scheduler for recurrence.

A scheduled Command whose only purpose is to wake a Saga instance (an `options` Aggregate whose unstored Event only that Saga consumes, triggered by the Saga's own `scheduleTask`) becomes a Deadline: `saga.deadline(name, dueAt, payload)` in the Saga, its old Event Reaction under `deadlines[name]`, and `saga.cancelDeadline(name)` or `saga.destroy()` where the old Saga let the task go stale. Its `only.ifExists()` is the default: a Deadline of a destroyed instance is cancelled. A route or Worker that sent such a Command to an existing instance sends a Saga Message instead (`sendSagaMessage(saga, name, payload, { to })`, a Gateway through an Access-map `sagaMessages` entry); a recurring external schedule that started a new instance sends one to a `start: true` handler. Saga Messages never reach Readmodels or Command waits, so a route that waited for the old Event needs another answer. Where the old Commands should stay, run them in a Worker instead: the Aggregate's Commands keep their schema and queue a Message, the Worker runs the old Command on an empty State, and each Event it applies goes as a Saga Message to the Sagas that reacted to it, the Reaction moved under `messages` (a `start: true` handler where it had no `only.ifExists()`). Import the old scheduler's pending tasks with `recordSagaMessages` (or `sendSagaMessage` with the task's id as `id`), so a repeated import keeps what is already pending.

Hand fixes that must precede replay:

- Move external calls from Sagas into Workers. Queue a Message and pass the recorded `ctx.idempotencyKey` to the provider. Inventory external writes from Command handlers, Sagas and Readmodel Reactions and express them as effects after commit. Readmodel Reactions must obtain changing business inputs from their Events.
- Existing Readmodel `app.getServices()` calls remain compatible when `readmodelServices` is omitted. To switch to Readmodel helpers, audit direct and indirect service calls, then supply only pure helpers as `readmodelServices` (or `{}` for none), with `Register.readmodelServices` for typed code. Move mutable lookups into Event payloads and external writes into Workers; copying the entire Services object preserves the old risks. Other contexts retain their existing service access. The Application inventory must establish every affected direct and transitive call site; a synthetic example does not supply that coverage.
- No fix is needed for the old `datejs` package: EventFabric parses its own times with the `Date` constructor, not `Date.parse`, which that package replaces with a function that returns a Date or null.
- Rewrite `_runtime`, connection and raw-bus accesses to public `sendCommand`, logger, hooks, services or Application-owned clients. Plugins register `start`, `shutdown` and `gateway` hooks; runtime model-load hooks are gone.
- Resolve every Access map review entry. Review tenant filtering on id reads, list/count/stream/native paths and SSE. The old stack did not enforce its Command rules, dropped a computed tenant filter on one query path and let Event subscriptions choose their own filters; EventFabric applies the Access map to every read and Notification, and the migration never recreates those omissions. Where a caller loses rows it saw before, fix the caller, not the rule. Closing previously ineffective Command rules is a separate Application behavior change after cutover.
- A Gateway listens on `127.0.0.1` and parses JSON only. Set `host: '0.0.0.0'` where a container port must be reachable, and add CORS and URL-encoded body middleware where clients relied on the old defaults (`legacyGateway` sets them).
- Resolve the flagged waits and check each generated `awaitCorrelated` result. Review HTTP accepted/rejected/failed/unknown outcomes and 202 responses for behind or missing Readmodels.

`draftReadmodelSchema(initialState, sampleDocuments, { dynamicPaths })` produces a closed draft-07 `schema`, a JavaScript export and a `reviews` list. It widens scalar evidence, derives array elements and nullable fields from samples and recognises `Date` values. Fields with no evidence, mixed types, dynamic keys or more than 20 observed nested keys use `x-store: json` and receive `// review:` comments. Resolve enum-bounded dynamic keys into declared properties by hand; add genuinely unbounded parents to `dynamicPaths`. Review every inventoried Readmodel schema, including null/empty-array fields, date strings, nested arrays, optional/null semantics and every JSON opt-in. A draft is not an approved schema. The old ViewModel stored each document's id in an `id` field and Reactions no longer do, so a draft holding `id` is listed: set it where the document is created (`view.set('id', view.id)`) or move readers to `_id`.

Enable the named `configs.recommended` export from `event-fabric/eslint-plugin` in flat ESLint config. It errors on clock/randomness in Event handlers, enrichers, Readmodel Reactions and Identities; Commands' Steps/Rules get clock warnings. Aggregate-level `rules` get the same clock warning. Saga Reactions may read the clock, while Saga Identities stay pure. A Saga is recognised under a `sagas` key, in a declaration whose name contains `saga`, in a file containing a `// @eventfabric-saga` comment, or by file name (default pattern `(^|[./-])saga(s|[./-]|$)`, overridable with the determinism rule option `{ sagaFiles: "<regex>" }`). An object with both `reactions` and `schema`, or anything under `readmodels`, is always a Readmodel. Rules recognise object declarations, named authoring functions/exports, assigned CommonJS shapes, imported UUID aliases and CommonJS crypto module/destructuring aliases. The recommended config also rejects default exports. Keep effectful helpers outside deterministic code: lint cannot prove arbitrary separately defined helper functions pure.

### A worked example

[`test/fixtures/legacy-slice/`](../test/fixtures/legacy-slice) holds a small synthetic dunning slice in the old framework's CommonJS style: an Aggregate, two Readmodels, a Saga, QueryBuilder reads, Gateway routes (a list and a REST command descriptor) and a Task. [`test/legacy-slice.test.ts`](../test/legacy-slice.test.ts) runs `migrateSource` over each file with `packages: 'cutover'`, checks the rewrites and review entries, then runs the migrated copies on an in-memory Application, the routes through a Gateway, and asserts that they behave as before:

|---|---|---|
| `aggregate.apply.opened(payload, metadata)` | `legacyMetadata(metadata, cmd.metadata)` | deep merge, Command values win |
| `aggregate.apply('reminded', payload)` | `aggregate.apply.reminded(payload)` | callable apply |
| `get('_revision')`, `state._revision` | `.revision` | Revision reads |
| `event.metadata.timestamp` in an Event handler | `event.timestamp` | commit time |
| enricher reading the State and setting `event.metadata` | `legacyEnricher(…)` | runs inside each `apply` on the State before that Event |
| `only.ifNotExists()` in a Command | unchanged | means the same in both stacks |
| `only.ifNotExists()` in a Reaction | removed | it allowed creation and still handled existing documents |
| `only.if(predicate)` | unchanged, from the new package | false skips the whole Reaction: no document |
| `'event:count'`, `'event:status'` keys | one Reaction with both functions | same functions, same order |
| `'event:customer'` key with its own Identity | a `reactionSets.customer` entry | its own document per customer, in the same collection |
| `query` map | `identity` through `legacyQueryIdentity` | old filter language, e.g. array membership |

| `await app.getDomain().billing.dunning(id)` in a Command | `….load()` | the other Aggregate's State, with `get(path)` |

The old toolkit's `only` is redirected with `replacements: { "require('legacy-toolkit')": "require('event-fabric')" }`. With `packages: 'coexistence'` the same files keep `event-fabric-next`, the new package's name while the old one is still installed as `event-fabric`. `compile` still refuses old Aggregate `options` such as `disablePersistence`. Declaring each Readmodel's schema stays a manual step.

Its last test plays the data cutover (see [Offline import and replay audit](#offline-import-and-replay-audit)): `migrateHistoricalEvent` turns an old stored Event into an EventFabric one (Revision base 0, Dates refused until `dates: 'iso'` is given), `store.import` keeps its id and timestamp, `migrateSagaState` refuses a pending old timeout and strips storage fields, and `importSagas` places the Saga state after the imported history. A new Application on that store then continues the case from its imported State.

## CLI and generated types

The default entry is `event-fabric.config.js`, exporting named `config` as an object or `config(env)` factory. `--config` overrides the file; `--env` overrides `EVENT_FABRIC_ENV` and is supplied to the factory. Config construction must keep model declarations readable without starting services or hooks.

Set `typesPath` and, for named Command schema references, `schemas` or `schemasDir`. During coexistence, set `typesModule: "event-fabric-next"` so the generated Register augments the new dependency. Run `event-fabric types`, then `event-fabric types --check` in CI. Generation reads declarations without running plugins, registering Readmodel schemas or starting consumers. It emits Event/Command name unions, Event payload interfaces (from Event `schema`s, `unknown` without one), Command payload interfaces and Readmodel document interfaces, including `Date` and optional fields that may be absent or `null`. There is no runtime constants file. Named/local refs are resolved; a missing schema is an error. `types --check` checks freshness, not the Application's code. Apply the generated mapped types to authoring maps, then run `tsc` (or `tsc --allowJs --checkJs` for JavaScript) in CI:

```ts
import type {
  EventReactions,
  EventIdentities,
} from "./event-fabric.generated.js";
export const reactions = {
  "sales.account.added": (event: any, vm: any) =>
    vm.set("total", event.payload.amount),
} satisfies EventReactions;
export const identity = {
  "sales.account.added": (event: any) => event.aggregate.id,
} satisfies EventIdentities;
```

In JavaScript put `/** @satisfies {import("./event-fabric.generated.js").EventReactions} */` immediately before the Reaction map declaration, and use `EventIdentities` for an Identity map. These checks reject unknown Event keys without runtime constants.

- `run --only commands:myApplication --only worker:mail` selects roles. Kinds are `gateway`, `commands`, `readmodels`, `saga`, `worker`, `outbox`, `relay`; `*` selects every name of a kind. `commands:myApplication/<context>` runs only one Context's Command handlers, as the old distributed entry's per-Context domain filter did; each Context has its own Command queues. No selection starts everything. SIGINT/SIGTERM drain and close the Application.
- `dev [--inspect]` starts the same CLI under Node's `--watch`; there is no framework watcher.
- `migrate --dry-run` prints the quoted SQL; `migrate` explicitly applies versioned Event store/Outbox/dead-letter/Lease/Checkpoint migrations. Startup never applies these migrations and refuses to start while any are pending, including the Event-type/Position index the Readmodel readers rely on.
- `rebuild api --swap manual` builds a shadow generation and reports its id. `rebuild --swap api` catches it up and atomically makes it active; without a positional group `--swap` always names the group, so groups called `auto` or `manual` work too. `rebuild api` swaps automatically. `rebuild api detail …` or `rebuild --all` rebuilds several groups at once, each in its own worker thread. The runtime fences ownership, drops the old generation after swap, and warns about at-or-later cross-group reads. Sagas cannot be rebuilt.
- `task ./task.mjs -- --flag value` calls named `run(ctx,args)` with config, services, sendCommand, awaitCorrelated, Readmodels, logger and bound `readStream`/`readAll`/`import`. It starts no consumers or plugin hooks, passes stdin through and exits nonzero on a throw. Services set up by a plugin are therefore missing in a Task: move their construction and cleanup into `setupServices`, which a Task runs and cleans up (README, Services).
- `dead-letters list`, `replay <id>`, `replay --all`, `discard <id>` operate on the durable ledger. Replay resets attempt counters while preserving the Message's id and Idempotency key. Discard emits a log line.
- `consumers status --json` reports durable Checkpoints, lag, Lease owner, halted Events and dependency waiting. `consumers retry <group>` requests an immediate retry. `consumers skip <group> --event <id> [--who operator]` asks for confirmation; `--yes` is explicit noninteractive confirmation. The Application refuses an Event other than the exact halted one. Saga audit and Checkpoint updates are atomic in Postgres. A Readmodel skip first fences local writes and rejects an already-applied Event, then records an epoch-checked durable audit in Postgres, then advances the local Checkpoint. If the process crashes after the audit, the next owner advances from the ledger without executing that Reaction. If it crashes before the audit, retry the operator command; no skip was recorded. Use `application.skipConsumer()` rather than calling the Event store port directly for a Readmodel. A group that no live replica's `instance:` row lists reports `undeclared` instead of its stored state, and emits no lag metric; nothing is marked while any live replica has yet to list its groups. `consumers retire <saga or workflow group>` deletes a removed Saga or Workflow group's Checkpoints, `layout:` row, pending Saga Messages and Deadlines, and its Saga state or Workflow instances (every `workflows` row of the group, running or finished) after confirmation (`--yes` skips it). It is refused while any live replica declares the group or any of its Partitions holds a Lease, so run it after every replica runs the new config. The state goes too because a Saga or Workflow added back later is a new group that starts where its `from` says, and with `from: "beginning"` old state or instances would double-apply its Events. Commands and Messages the Saga already recorded stay in the Outbox and are delivered when due, as in billing's former `overdue` Saga, whose delayed `markOverdue` Commands re-check the Invoice; drop such rows only with application-specific SQL. Readmodel groups cannot be retired this way, because their Lease epochs also live in the Readmodel store.

## Offline import and replay audit

This procedure assumes an offline cutover: all source writers are stopped and no client retries a pre-cutover Command. Verify that operational assumption for the Application; the synthetic examples do not establish it.

1. Inventory every source Event store and select the authoritative log explicitly. If multiple stores should hold the same history, reconcile content and order and stop on unresolved differences. Determine original commit order and source Revision base explicitly.
2. Create a fresh scratch Postgres schema and run `migrate`. Import Events in that original order. `migrateHistoricalEvent(source,{revisionBase:0|1, dates})` preserves Event ids, timestamps and Revisions (adding one only for explicitly zero-based sources), records Schema version 1, maps the old chain id to Correlation id and leaves Causation id empty. Pass the domain Event's own id, not the storage wrapper's, and pick `revisionBase` from the Revision you pass: an old storage Revision starts at 0, while the domain Revision is already that plus one. Storage-wrapper fields such as `dispatched` are not part of the Event. A Date timestamp becomes its ISO string. A Date in the payload or metadata is refused with its path unless `dates: 'iso' | 'epoch'` is chosen, and other BSON values (ObjectId and the like) are refused with their path; convert them by hand. It moves framework metadata into the envelope and returns review entries for email-bearing metadata. Resolve every review before import. New Positions come from the import transaction, in the order of each `import` call's array; never reuse old Positions. Each call writes its batch in a few set-based statements, and a later call may continue existing Streams from their next Revision, so a log can be imported ahead of cutover and its tail at the freeze. The old Mongo store reserves an Event's position before it inserts the Event, so while it runs a lower position can become visible after a higher one: import ahead only up to Events committed a few minutes before the scan, and at the freeze check that the old store holds exactly as many Events at or before the last imported position as were imported, before importing the rest. Import does not record the Events' Command ids, so an old Command id sent again after cutover is handled as a new Command, not as a Duplicate. Old response caches and deduplication history are reset; this is safe only while the data is dormant and no client retries a pre-cutover Command.
3. Fold every Stream in the expected manifest and compare final states. Replay every recorded Command that remains comparable, comparing Event names, payloads and enriched metadata with the same clock and stubbed external services. Deleted Commands and Commands depending on unavailable services need explicit per-Command skip reasons; count and review every skipped Command. Recorded Events show what the source code did when each Command ran, so code changed since then makes them a poor oracle. Instead, handle each Command on the old runtime too (the pre-migration source, in memory, with Aggregates loaded from the same history), and compare the two. Give both runs the same clock, random ids, id counters and CRUD results: run CRUD calls once and hand the second run the recorded results, against CRUD copies that belong to the audit.
4. Rebuild every Readmodel group from the imported log, then compare every document with the original store after removing only documented legacy per-document guards. A halted Consumer group is a bug, not a reason to skip. Permit differences only on an explained list tied to decisions: clock fixes, at-or-later cross-group reads, removed mutable CRUD reads or schema typing. Require zero unexplained differences.

`auditReplay()` in `dist/migration/audit.js` performs supplied state/Command comparisons and optional full Readmodel rebuild comparisons without starting Sagas or Workers. `auditFixtureFiles()` reads the `events.jsonl`, `states.jsonl` and `commands.jsonl` fixture files read-only. Create an Application-owned audit config exporting named `audit` with `definitions`, optional kernel services/validation, `stateOmit`, `skipCommand`, and exact-id `explanations` entries with both `reason` and `decision`. Set `AUDIT_CONFIG`, `FIXTURE_DIRECTORY` and `AUDIT_REPORT` to the config, fixture directory and output file, then run:

```sh
node dist/migration/cli.js --config "$AUDIT_CONFIG" \
  --fixtures "$FIXTURE_DIRECTORY" --revision-base 1 --output "$AUDIT_REPORT"
```

The runner reports checked/skipped counts and returns nonzero for unexplained differences. Use its optional Readmodel audit input for all-document comparisons; the fixture CLI covers Streams and Commands. Never commit fixture payloads or reports. The implementation's synthetic audit test verifies state folding, Command replay and a complete Readmodel rebuild while proving that Saga Reactions are not replayed. A successful supplied comparison is partial evidence. `passed` permits explained differences, skipped Commands and missing Readmodel expectations. Require exact expected coverage, explicit outcomes/effects and resolved omissions using the [readiness contract](migration-compatibility.md#coverage-manifest-and-readiness); synthetic success does not establish Application readiness.

## Final cutover and rollback

1. Confirm all old writers are stopped and keep old stores untouched.
2. Run `migrate` on the new schema; import the reconciled Event log.
3. Import every historical Saga instance in the expected manifest, including finished instances. `migrateSagaState()` removes `_commitStamp`, `_hash`, empty `_commands` and an unset timeout (`_timeoutAt`, `_timeoutCommands`). It refuses nonempty pending Commands and a pending timeout: the runtime has no Saga timeouts, so a kept timer would never fire. Reconcile each one as a delayed Command (`notBefore`) or retire it. The old Mongo store kept BSON values, but imported state is JSON. A Date is refused with its path unless you pass `{ dates: 'iso' }` or `{ dates: 'epoch' }`; then update code that called Date methods on it. Other non-plain values (ObjectId, Binary and the like) are refused with their path; convert them by hand. At run time, a Reaction may still set a Date: the Saga state is stored in its JSON form after each Reaction, so the Reaction itself sees its Date, and later Events and reloads see the ISO text, as Command and Message payloads already do. Map each old collection to its exact `saga:<name>` group and to the ids the new Identity resolves. Set every Saga's Checkpoint to the imported log head using `importSagas`. Call it for every declared Saga group, with `[]` for a group with no documents: a group with no Checkpoint is new and starts where its `from` says (`now` by default, so an Event imported after the replica started would be handled again; `beginning` handles all history again). Never replay Sagas to reconstruct state.
4. Rebuild every Readmodel group into its chosen store and reviewed schema, or import it: once a rehearsal has rebuilt a group from the imported log and compared it with the old store with zero unexplained differences, `importReadmodels(group, documents, { position })` can take over the old store's documents at the imported log head instead of rebuilding them. Remove the documented legacy per-document guards from each document first, and keep the old store untouched. Begin with empty Outbox, dead letters and Worker queues. Recreate only delayed work the Application still wants.
5. Require the complete offline audit, lint, generated-type freshness and `tsc`/JavaScript `checkJs` checks to pass. Start Consumer groups, Workers and Gateways.
6. Smoke-test one Command per Gateway, read-your-writes, SSE reconnect/heartbeat, and one Worker Message with a stable provider Idempotency key. Verify no halted groups, expected dependency waiting and reader lag alerts.
7. Reopen traffic only after approval of that concrete audit. Before the first real new Command, rollback is restarting the old stack. After that Command, rollback would lose new Events: there is no reverse synchronisation. If an import step fails, use a fresh scratch schema and repeat from migrations; an append-only import is not a resumable overwrite operation.
